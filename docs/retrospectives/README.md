# Retrospectives

Lightweight retrospective summaries live here, one file per retrospective:
`YYYY-MM-DD.md`. When and how to hold one is defined in
`.claude/rules/process-improvement.md`.

Suggested shape (keep it short):

```markdown
# Retrospective YYYY-MM-DD

Scope: PRs #a–#b / trigger for this retro

## Went well
## Went poorly
## Changes proposed
- ... (link the `process` issue opened for each)
```

The file records the observation; any actual process change goes through a
`process` issue and a reviewed PR.
