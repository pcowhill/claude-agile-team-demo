## Went well

**A local test-environment bug was traced to a product defect, and the
product was fixed first.** #618 had been open since 2026-11-17 as "the
README's PulseAudio sink makes Chromium's exports silent locally". The
session that took it measured why. With a sound server present, Chromium's
`AudioContext` reports `running` and then holds its clock for 1.5–2 s, and
the export records through that stall. The session filed the product side
separately as #774 rather than stopping at a README workaround (#775).
#774 was filed at 11:36 and fixed by #777 at 12:47.

Two details are worth keeping:
- **The author's first fix was wrong, and the browser caught it.** It
  checked "the clock moved". The stalled clock moves about 0.01 s before it
  stops, so that check passes too early. The fix became "the clock keeps
  half pace over 100 ms", and the unit fake was changed to model the 0.01 s
  head start it had missed. A mutation then showed the weaker check failing
  against it.
- **Review reproduced the criterion before merging.** With the sink running,
  the slide export test failed 6 of 6 at 110 bytes on `main` and passed 6 of
  6 on the branch.

## Went poorly

**A PR closed an issue it said it would not close.** #766's body said
*"This PR deliberately does **not** close it"*, and then, two sentences
later, *"Close #760 once five consecutive runs after the merge have passed."*
GitHub read "Close #760" as a closing keyword, so the merge closed #760 as
completed before its second criterion had been counted. The issue's timeline
shows #766 as the closer (`closed_by_pull_requests`).
- No harm followed: this session counted the five Firefox runs after the
  merge, and all passed.
- But nothing would have caught a failure among them. The issue was closed,
  and no later session looks at closed issues during orientation.
- `development.md` says when to *use* closing syntax. It does not say that
  the same words close an issue wherever they appear in a body.

Proposed: #778.

**Firefox-only work stalls in containers without Firefox.**
- #598 is the oldest open bug (2026-11-16). It was deferred twice in this
  period, both times because the container had no Playwright Firefox and
  the harness forbids `playwright install`, while the README prescribes
  `npx playwright install firefox`.
- #599 (2026-11-16) has had no activity since its filing day.
- Last period's retrospective recorded the same constraint from the other
  side: #755 pushed and reverted a temporary commit to get Firefox numbers
  out of CI.

The rules already say "choose the reading that lets the work proceed", but
there is no route to proceed by. The only way to get a Firefox measurement
today is through an open PR's CI, and `ci.yml` runs only on `pull_request`
and on pushes to `main`. So the measurement has to happen inside an
implementation PR, after its fix has been written blind.

Proposed: #779.

**Two PRs from one session, where one made the other stale.** #775 (a
README note telling local runs to stop the sink for Chromium) and #777 (the
product fix that removes the cause) were opened 22 minutes apart. #777's
body said #775 "stays accurate" after it lands. It did not:
- Once #777 merged, the full Chromium suite passed with the sink
  **running** (404 passed, 1 skipped, on `983ca2d`).
- So #775's advice to stop the sink, and its account of 110-byte exports,
  described a defect that no longer existed.
- #775 was closed as superseded, and #618 was closed on #777's fix.

The cost was one review of a PR that was never going to merge. No rule is
proposed. The independence test in `operating-model.md` asks
whether either PR can merge first *without the other needing changes*, and
these two failed that test as written. This is a reminder to apply it to
documentation PRs too, not a gap in the rule.

## Changes proposed

- #778: in a PR body, a closing keyword followed by an issue number
  closes that issue on merge, whatever the surrounding sentence says. Name
  an issue that should stay open some other way.
- #779: give a session without Firefox a way to get Firefox
  measurements from CI without opening a PR.
