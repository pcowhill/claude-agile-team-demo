## Went well

**Main was green the entire period — including the fix that made it so.** All
28 main-branch runs concluded `success`. The previous retrospective's
dominant theme (the apt-lock hang that cancelled four main runs) ended with
#90: zero recurrences since. The three-iteration diagnostic arc was costly,
but the third fix held.

**The deploy gate proposed last retrospective landed and demonstrably works.**
#91 → #106 rewired `deploy.yml` to trigger on CI's `workflow_run` success
instead of raw pushes; every deploy this period (runs 41–50) launched only
after its commit's CI run succeeded. "CI protects production" is now
mechanism, not aspiration — the standing gap named in the 2026-08-20 retro is
closed.

**The slice pattern scaled to five, driven end-to-end by customer feedback.**
Feedback #100 ("add music") became slices #101–#105 and merged as
#109/#110/#111/#113/#115 in dependency order — the largest series yet, after
three- and two-slice epics (#107/#108 shipped feedback #92's embedded media
the same way). Each slice carried its own e2e evidence and independent
review; none needed a follow-up fix to its own scope. Reviews stayed
substantive at this cadence: #115's review re-verified the gain-composition
paths against the preview's, and #108's review byte-checked the save modes
through the injectable seam.

**The customer is steering the process itself, and the loop closed fast.**
#93 and #95 (customer `process` issues about origin labels and templates)
merged as #96/#99 within a day, and every customer issue since arrives
pre-labeled by template. Feedback → scoped issue → merged PR latency is now
routinely same-day.

**A discovered trap became an issue, a proper fix, and evidence-first
review.** The preview-zoom spec's hidden coupling (below) was filed as #116
with the exact failure numbers, fixed by #117 choosing the
"stable-by-construction" option over a clamp that would have weakened the
spec's assertions, and its review reproduced the trap on the pre-fix spec
before merging — reproduce-first on both sides of the handoff.

## Went poorly

**Product copy bent to test convenience before the trap was named.** While
#115 updated the export panel's note, the preview-zoom e2e spec failed —
its derived zoom scale silently depended on how many lines unrelated panel
text wrapped to. The authoring session shipped a *shortened* note inside #115
to get green (recorded honestly in the commit message), then filed #116. The
right endgame happened (#117 pinned the spec's viewport so no panel copy can
move its geometry), but for one merge the test suite, not the product,
decided user-facing wording. The general lesson, recorded here for spec
authors: an e2e spec that derives assertions from live layout must pin the
layout inputs it depends on (viewport, in this case), or copy edits anywhere
in the app become invisible test hazards.
