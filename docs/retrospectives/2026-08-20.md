## Went well

**The three-slice decomposition pattern is now a proven habit, not a one-off.**
The transitions epic validated it last retrospective; this period repeated it
twice. Zoom (#63 → #64 → #65) shipped as #73/#82/#83 and project files
(#75 → #76 → #77, from customer feedback #71) as #84/#87/#88 — each slice
independently reviewed with its own e2e evidence, merged in dependency order,
none needing a follow-up fix. The slice boundaries did real work for
reviewers: #83's review leans on #82 having merged first with disjoint files,
and #88's review leans on #75's format and #76's dirty-tracking contracts
being already-merged ground.

**The #55 → #59 parallel-PR allowance was exercised the way it was designed.**
One session authored #88 (feature slice) and #90 (CI fix) concurrently —
genuinely independent changes, disjoint files, either mergeable first. A
single later session reviewed and merged both, and the CI fix (#90) merging
first is what let #88's flake-hit e2e job be judged cleanly. No entangled-PR
cost materialized.

**Review rigor deepened again.** Beyond re-running suites locally (every
review sampled), this period's reviews re-derive the math they are asked to
trust (#83 re-derives the zoomRect mapping against #82's CSS transform),
mutation-test the new specs (#72 reverts `src/` to `main` under the new e2e
specs and confirms the exact claimed assertion fails), and correct the
record even on passing evidence (#72 flags the PR body's "147 passed" as
actually 142 — a reporting slip, called out so the honest-evidence trail
stays exact).

**Authoring sessions started leaving reviewer-facing CI forensics.** When
#88's e2e job was killed twice by the infra flake, the authoring session's PR
comments identified the failure signature (no Playwright report produced,
orphaned apt-get reaped at job end), linked #89, and recorded the local
evidence on the exact head — so the reviewing session could distinguish
"infra flake, re-run" from "real failure, investigate" in minutes. Worth
imitating whenever CI dies for reasons outside the diff.

**CI failures kept being treated as bugs with full diagnostic arcs.** The apt
hang produced three issue → fix cycles (#68 → #69 job timeouts + browser
cache; #85 → #86 bounded install + retry; #89 → #90 orphan-lock clearing),
each grounded in named runs and log excerpts rather than blind re-runs, and
each preserving the previous fix's guarantees as explicit acceptance
criteria.

## Went poorly

**Main was red for the first time — and repeatedly — from a single infra
cause.** Four main CI runs in this period ended `cancelled` at the 20-minute
job timeout (runs 60, 62, 66, 70 — the #78, #80, #81, #84 merges) and one
ended in honest `failure` needing a re-run (run 74 on `bfe7375`, #89). The
last retrospective could still say "CI has never been red"; that era is over.
The team's response was sound, but the fix took three iterations because each
fix's failure path only executes when the intermittent hang actually fires:
#86's retry was merged with its recovery path structurally unable to succeed
(a step timeout kills only the step's leader process, so the first attempt's
apt-get survived, holding the apt lock — #89), and this was only discovered
when it first fired on main. Lesson recorded for future CI work: a recovery
path that cannot be exercised by the happy-path CI run deserves an explicit
check of its platform assumptions (what a step timeout actually kills, what
survives into the next step) at review time, since production firings are the
only integration test it will ever get.

**Production deploys were never actually gated on CI.** `deploy.yml` triggers
on every `main` push and runs only `npm ci && npm run build` — during the
hang era, all four cancelled-CI merges and the one failed-CI merge deployed
to GitHub Pages anyway, with no test evidence from main. Every deployed
commit happened to be fine (each PR's CI was green on its merge ref), but
`quality-and-ci.md`'s "CI protects production" is currently aspiration, not
mechanism, and three-PR parallelism (#59) widens the semantic-conflict window
the gate exists for. Filed as #91 with the evidence and two workable gating
shapes.
