**Customer feedback turned into structural fixes, not only point fixes.**

**The flake-watch rule found what "green" had been hiding.** CI's
Playwright retries mean a flaky e2e test almost never fails a job. All 31
runs here concluded `success` on attempt 1. #595's author nonetheless read
the job logs, not just the conclusions, and found #553's test reported
`flaky` in **15 of 20** runs (488–507). This session re-read run 530's
log: `1 flaky … export-base-readiness.spec.ts:83`. #553 is an active
flake, not a dormant watch, and it is now visibly so.

**A review found a vacuous check by measuring it.** #601's fix to
`expectNoWrap` was re-run with the CSS mutated. It fails 22 of 27 wrapped
Contents links where the old comparison failed 0, so the fix is real.
Then the same mutation applied to the shortcut table's key combos showed
both the old and the new check failing 0 of 14, with the long combos
wrapped onto 2–3 lines. Filed as #603, with the measurement. → proposed below.

## Went poorly

**The previous retrospective's own instruction was not carried out, and
the customer had to ask.** The 2026-09-19 retrospective ended: *"#442
reaches 'a few weeks' at the end of September; a session then should close
it `not_planned` on its own terms …"* No session did. #442 sat open for
another seven weeks, with three "not closing yet" comments before that,
until the customer wrote #588: *"some of them have been around for a long
time and are never addressed."* A retrospective sentence addressed to "a
session then" is addressed to nobody: nothing in orientation reads old
retrospectives. #595 fixed this one case the right way, with a count that
orientation step 5 points at, and this session closed #442 and #538 under
it. The general lesson is already a rule (#302: a trigger nothing in
orientation points at goes unnoticed). Recorded so the next retrospective
does not repeat the shape: a deferred action belongs on an issue, not in
a retrospective's prose.

**Firefox defects reached the customer, one after another, under a
Chromium-only CI.** #579 (screen recording never concluded), #591/#593
(number fields never applied), #584, #585 and #597 (guide deep links).
Each was a real defect that CI could not have seen. The structural fix is
in (#601), and about a third of the suite is still excluded under Firefox,
each exclusion owned by an issue. So the remaining risk is named, not
hidden.

**Retries made a flaky test look healthy for two months.** #553 was filed
on 2026-09-18 as a single sighting. Through retries it has flaked on most
runs since, and no run failed, so nobody looked. #595's rule now counts
flaky-on-retry as a recurrence. That closes the gap for watched tests, but
not for unwatched ones: a test that starts flaking today is invisible
until someone reads a log. Not proposing a change from one instance.
#601's first Firefox run reported its flake on the log's last lines, and
it was filed the same day (#602), which is the habit that works.

**A rule's own example was the vacuous check.** `development.md`
recommends `scrollWidth <= clientWidth` as the example check for "a label
not wrapping". That comparison measures overflow. It is `0 <= 0` for an
inline element in Chromium, and passes for a block whose text wraps. The
two checks above that caught nothing were written in its shape. → #605.

Nothing else. The seven-week gap, the Firefox defects and the retry-hidden
