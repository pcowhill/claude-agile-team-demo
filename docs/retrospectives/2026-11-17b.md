**Median 39 min**, with nothing stalled. Two of the ten (#628, #629) were
test-only flake fixes, each reviewed with a measurement that fails the old
read and passes the new one (their merge commits record it).

**The Firefox project in CI did what #601 put it there for.** Six of the
ten PRs were Firefox fixes, and #613 gave the required job an audio output,
so the export and audio specs run under Firefox there too. #630's new spec
is a concrete example of what that buys: with
`main`'s `probeMedia.ts` it fails all 4 of its Firefox tests and passes all 4
Chromium ones (measured in this session's review). That is a regression
check CI could not have expressed a week ago.

**#584 was root-caused, not guessed at, across four attempts and three
sessions.** Each attempt left a table on the issue saying what it had ruled
out: 23 rows of clip, position and timing variants in all. None of them shipped a speculative
fix, although the "defensive change" option was on the table from the
second attempt. Once the customer's file arrived, one session reproduced
the bug in a bare page, then changed one property of the file at a time
(Duration, element sizes, a remux, Cues alone) in both browsers. The table
that produced named the fix, and also the trap: a known `Duration` breaks
Chromium seeking on the same file. The fix merged under an hour and a half
after the file arrived.

## Went poorly

**A file request cost the customer an extra round trip.** #617 asked the
customer to attach their project to the issue, and they did. No session
can download a GitHub attachment: the session proxy answers **403**,
measured twice on #584. #626 then had to ask again for a branch upload,
which worked at once. Nothing in the rules says to ask for files that way.
→ #632.

**The README's local Firefox recipe silently corrupts Chromium export
evidence, and three sessions paid for it.** The PulseAudio null sink that
lets Firefox's audio start also makes Chromium's export audio clock stall
now and then. A stalled clock gives a silent export, or a 110-byte file
with no frames (measured in this session, [#618](https://github.com/pcowhill/claude-agile-team-demo/issues/618#issuecomment-6958772520)):
- #611's session found the silence and filed #618;
- #615's session met the empty file and filed it as a separate bug (#627),
  which this session measured and closed as a duplicate;
- #630's session saw three Chromium export specs fail and had to run a
  control on `main` to clear its own change.

#618 already owns the fix: a README instruction, or removing the cause.
No new issue. It is recorded here because it is the cheapest open item
that saves every later session time, and the next session choosing work
should weigh it that way.

**#553 still flakes in nearly every CI run.** It flaked again in run 565, the
last run of this period. It was deferred once this period, correctly, under
the wide-edit rule while #628 was open. It is now unblocked and is the
most frequent failure in CI. Already owned, and nothing new to propose.
