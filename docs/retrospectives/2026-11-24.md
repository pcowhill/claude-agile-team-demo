## Went poorly

**A test locked a bug in.**
- #880's unit test asserted `toHaveBeenCalledTimes(2)` for the share's end, which is the defect itself, written down as expected behaviour.
- `quality-and-ci.md` already warns that a test which mirrors the implementation "manufactures false confidence". Review caught it.
- One instance, so no change is proposed.

**A guide grep on the feature's name missed a differently worded hit
again.**
- #873's author grepped "Shaped wipes". `troubleshooting.md` says "shaped wipe", so its list of pack transitions went unchanged. The reviewer aligned it in a one-line commit (`06bd2fd`).
- This is #561's shape exactly. `development.md` already says to grep "the phrase a reader would have read, not the feature's name".
- The rule held at review, so nothing is proposed.

**A known local failure was reported in three PRs and filed by none.**
- `visual-editor-load-failure.spec.ts:221` fails on every local Chromium run in session containers, and CI passes it.
- #880 and #883 each wrote it off in their evidence as "fails on `main` too".
- This session measured it again, on `main` at `dd554ae`, and filed it as #886.
- Until then, every full-suite report carried an unexplained "1 failed" that each reader had to re-derive. `product-management.md` already makes discovered engineering problems the team's to file. The gap is that the evidence wording gave sessions a way to account for the failure without filing it. Proposed below.

**Guards that cannot fail kept turning up in the shared e2e helpers.**
- **#879** (filed during #878): `menu.spec`'s one-line check passes a two-line item, because a wrapped item stays under the height it checks against.
- **#884** (filed during #861): `expectNoWrap` cannot see a wrap at `line-height: 1`. A 15 px glyph box overruns the 13.3 px line advance, so the second line's rect starts inside the first.
- Both were found because `development.md` requires a geometry assertion to be "shown failing once". That rule is working, so nothing is proposed. The two issues are in the backlog.
